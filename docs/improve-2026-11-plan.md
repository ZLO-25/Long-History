# 依三角色試用報告改良：規劃書（2026-11-15）

- 依據：`docs/review-2026-11-15.md`（三角色試用報告，34 項建議）
- ZL 決定（2026-11-15）：34 項全做；Fable 5.2 medium 規劃與查核、Sonnet 5.5 medium 執行
- 限制不變：靜態網站、無後端、不串 AI；卡片事實要有來源並獨立查核；commit 用中文

## 目標

把網站從「寫得很好、附少量習題的互動讀本」變成「學生做得完、學得進去，老師敢派作業，內容對得上課綱」的學習系統。

## 分批（每批做完就驗收、推 main、上線）

```
 第 1 批         第 2 批            第 3 批            第 4 批           第 5 批
 壞掉的先修  →  一課做得完     →  老師敢派作業   →  內容補洞     →   收尾
 #1–7           #8–16              #17–24             #25–34            第 5 級
 程式＋資料      程式 → 題目         首頁、學習單、      新卡、新單元       無障礙、小字
                                    複習、課綱標示      （要查證，最久）   平板、深色…
```

每一批的流程相同：

```
 Fable 寫工作單（誰改哪些檔、驗收條件）
        ▼
 Sonnet 實作（每人一組不重疊的檔案）
        ▼
 Fable 驗收：typecheck、build（含 validate）、既有 QA、新測試、實際開畫面看
        ▼            └ 內容類另加「沒參與寫作的人獨立查核」
 推 main → 等 Pages 部署成功 → 回報
```

## 第 5 批：收尾

無障礙（換步焦點、role=status、h1）、手機最小字級 12px 與可點範圍、平板版面、專題製圖備註不外露、關係網人名、壞網址訊息、決策題補第三條路、故事考考自己分散並留紀錄、「上次做到一半」依時間、深色模式、故事地圖考古文化名、搜尋近似結果折疊。

## 風險與做法

- **內容量大**：第 2 批要改 43 個單元、第 4 批要寫新卡。Sonnet 改題目曾偷換選項順序，所以每次都用程式比對 answer 位置與選項集合。
- **不能弄丟的優點**：爭議並列、掩卷自思、今日對照先問哪裡不成立、故事閱讀頁、效能。每批驗收都跑既有 QA。
- **進度資料相容**：localStorage 的舊進度不能壞；新欄位都向下相容。
- **用量上限**：背景 agent 可能中途停，工作單要寫清楚「已完成清單」方便接手。
