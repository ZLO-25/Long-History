# 前因／後果（causes / effects）

使用者回饋：「每張卡像獨立事件」。卡片原本的 `links` 只說「相關」，沒說「為什麼相關」。
`causes`／`effects` 把連結加上**動詞**：誰造成誰、怎麼造成、強度多大、根據哪個來源。

```
  ← 前因（causes）：X ──[關係]──▶ 本卡     「從哪裡來」
┌──────────────┐
│     本卡      │
└──────────────┘
  → 後果（effects）：本卡 ──[關係]──▶ Y    「往哪裡去」
```

畫面上：卡片頂端「從哪裡來」、卡片底部「往哪裡去」。另一張卡的 causes 寫到本卡時，
本卡的「往哪裡去」會自動出現它（反向不用再寫一次）。兩邊都寫了也沒關係，build 會合併。

## 寫法

寫在卡片 frontmatter，`links:` 下一行：

```yaml
causes:
  - { id: finance-taiwan-1949-currency, rel: 促成, why: 接收後政府大量印鈔、米糧統制，物價飛漲讓民怨越積越深。, src: [s1, s5] }
  - { id: war-chinese-civil-war, rel: 背景, why: 內戰需要錢和米，臺灣的物資被大量調往大陸。, src: [s5] }
effects:
  - { id: event-taiwan-martial-law, rel: 背景, why: 事件後的鎮壓與清鄉讓社會長期不敢談政治，為之後的戒嚴統治鋪路。, src: [s1, s3], disputed: true }
```

| 欄位 | 說明 |
| --- | --- |
| `id` | 對方是哪張卡。**只能用 `id`**：完整的歷史教學不留「尚無卡片」的灰字。想寫的事件還沒有卡，就先補一張（摘要卡即可，見下方「補卡」），再用 `id` 指向它；補不了就不要寫這條。`name` 會被 validate 擋下 |
| `rel` | 關係類型，四選一（見下） |
| `why` | 一句話（80 字內）說明「怎麼造成的」。國中生看得懂，說出機制（因為…所以…），不要只重述事件名。不放 `[s1]` 代號 |
| `src` | 根據的來源：本卡的 `s1`，或別張卡的 `卡片id:s3` |
| `disputed` | 史家對這個因果看法不一時寫 `true`，畫面上標「史家看法不一」 |

## 四種關係（由強到弱）

| rel | 意思 | 例子 |
| --- | --- | --- |
| 直接引發 | 這件事直接點燃了另一件事，時間緊接著 | 斐迪南大公遇刺 → 第一次世界大戰 |
| 促成 | 是原因之一，但不是唯一原因 | 戰後通膨 → 二二八事件 |
| 背景 | 提供條件、讓後來的事有可能發生，但不直接推動 | 大航海時代的航線 → 荷蘭人來到臺灣 |
| 回應 | 後一件事是對前一件事的反應、對策或反彈 | 黑船來航 → 明治維新 |

挑最弱、但仍然正確的那一個。拿不準「直接引發」還是「促成」，就寫「促成」。

## 規則（歷史學者的底線）

1. **只寫查得到的因果。** 這個因果必須在本卡或對方卡的內文、或它們引用的來源裡寫到。不新增卡片內文沒有、來源沒有的史實。
2. **多因不單因。** 一件大事通常有好幾個前因；不要只寫一個，讓學生以為「X 造成 Y」就是全部。
3. **跨地區要有根據。** 例如「美洲白銀 → 明朝一條鞭法」可以寫，但必須有來源明確這樣論證。
4. **時間不能倒流。** 原因開始的年份不能晚於結果結束的年份（validate 會擋）。
5. **有爭議就標。** 史家對「是不是原因」「有多重要」看法不一時，寫 `disputed: true`，`why` 用「有學者認為…」。
6. **不是相似，是造成。** 「兩件事很像」是 `counterparts`（中西對照）或結構標籤的工作，不寫在這裡。

## 補卡（2026-11-02）

早期允許寫 `name`（尚無卡片的事件），畫面上以灰字「尚無卡片」顯示，一度累積約 360 條。
2026-11-02 依「完整教學不該有缺口」的要求一次補齊：

```
360 條灰字
 ├─ 被多條因果用到、值得獨立成卡的事件 → 補 94 張摘要卡（每張 ≥3 個來源、獨立查核）→ 改用 id
 ├─ 其實就是某張既有卡的一部分（例：「林則徐虎門銷煙」就在鴉片戰爭卡裡）→ 改指那張卡
 └─ 只是本卡內部的細節、或找不到夠格的卡 → 刪掉這條（內容仍寫在卡片本文）
```

改指之後若造成時間倒流、重複或互指，validate 會報錯／警告，逐條人工處理。

## 數量

每張卡前因 1–3 條、後果 1–3 條就好，挑最重要的。學習卡至少要有一條（validate 會警告）。

## 故事線（data/storylines.yaml）

故事線是**沿著前因／後果的箭頭**走出來的跨時代路線。每一站之間必須有一條 causes／effects 關係，
畫面上兩站中間的「橋」就是那條關係的 `why`，所以故事線不寫新史實。見 docs/storylines.md。
