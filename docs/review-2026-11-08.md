## 四、效能

### 做了什麼

```
之前：index.json 7.3 MB（gzip 2.25 MB）── 全部下載、解析完才畫第一個畫面

之後：index.json 3.1 MB（gzip 0.97 MB）── 時間軸、地圖、清單、搜尋、單元、專題結構
        │ 畫面先出來
        ▼
      index-detail.json 4.2 MB（gzip 1.40 MB）── 卡片各節內文、來源、前因後果、學習卡全文
        背景下載；到了才把「載入卡片內容…」換成內容
        （網址直接指到卡片／單元／專題時，index.html 一開始就同時抓）
```

1. **資料拆兩個檔**（scripts/build-index.ts、src/App.tsx `mergeDetail`）：長內文直接寫進原本的卡片物件，地圖、時間軸、搜尋索引不必重算。需要內文的面板在內文到之前顯示「載入卡片內容…」。
2. **簡轉繁字典不再於空閒時預載**：解析一次要 0.2–0.3 秒（CPU 降速 4 倍時），多數人用不到；改成點進搜尋框才載。
3. **別名量尺**包在 `contain: strict` 的盒子裡，量高度時不整頁重排。
4. 地圖各圖層的重畫條件改看實際用到的資料（疆域、路線、今日層），不因卡片內文到達而重畫。
5. QA 腳本共用 `scripts/qa/load-index.cjs` 讀兩個檔。

### 量測（gzip 伺服器模擬 GitHub Pages、CPU 降速 4 倍；兩次平均）

| 情境 | 10 Mbps 之前 | 10 Mbps 之後 | 3 Mbps 之前 | 3 Mbps 之後 |
|---|---|---|---|---|
| 研究模式出現時間軸 | 3.7 秒 | **2.5 秒** | 8.3 秒 | **4.6 秒** |
| 學習模式首頁出現 | 3.3 秒 | **2.2 秒** | 8.0 秒 | **4.4 秒** |
| 直接開學習卡：頁面框架 | 3.4 秒 | **2.3 秒** | 7.9 秒 | **6.7 秒** |
| 直接開學習卡：故事內文 | 3.5 秒 | 3.6–4.0 秒 | 8.0 秒 | 9.3 秒 |

一般入口（首頁）在慢網路快了約 45%；**直接用連結打開某張卡**時，框架比較早出來，但內文反而慢約 1 秒（兩個檔同時下載互搶頻寬，加上多一次解析）。這是取捨：多數人從首頁進來。

本機無限速（scripts/qa/perf.cjs）時，時間軸縮放／拖曳、地圖平移都沒有長任務；載入時 JSON 解析從約 240ms 降到約 100ms。「搜尋打字」的長任務變多，因為字典改成第一次搜尋時才載（之前算在載入時間裡）。
