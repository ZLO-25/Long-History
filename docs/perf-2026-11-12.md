# 載入變慢的原因與修正（2026-11-12）

做法：Fable 5.2（medium）量測、找原因、寫計畫與驗收條件；Sonnet 5.5（medium）實作；Fable 看差異、重新量一次再上線。

## 一、為什麼感覺變慢

首頁其實變快了，慢的是「首頁出現之後、點東西」的那幾秒。

```
0s        3.6s                            10.7s
│ 首頁出現 │ 點單元、點卡片都顯示「載入中」   │ 恢復正常
          └─ 在等 1.7MB 的背景大檔 index-detail.json ─┘
             它排在地圖元件（287KB）和古道資料（517KB）後面
```

11-11 的效能調整把單元每一步的內文也搬進這個大檔，首頁快了 1.5 秒，但點單元從「馬上有」變成「等大檔」。網路越慢，這段空窗越長。另外大檔的版本用的是建置時間，所以每次網站更新（最近一天好幾次）都要重新下載 1.7MB。

## 二、怎麼修

```
之前：點任何單元／卡片 ──等──▶ 整包 1.7MB
現在：點單元 ──▶ data/units/<id>.json（平均 31KB，含它用到的卡）
      點卡片 ──▶ data/cards/<id>.json（幾 KB）
      滑鼠移上去／手指碰到就先抓，點下去通常已經到了
      整包改成背景暖機，到了之後一切照舊
```

1. **點什麼抓什麼**：建置時多寫每個單元一個小檔；新模組 `src/lib/detail.ts`（`ensureCards`、`ensureUnits`、`intent` 預取）。各畫面只等自己要的那幾項，只有「結構對照」（要掃所有卡片內文）仍等整包。
2. **下載順序**：畫面要的小檔 → 底圖 → 整包 → 古道（最後）。
3. **不重抓沒變的資料**：整包版本改成內容雜湊（`index.json` 的 `detailV`），內容沒變時更新網站不會重新下載。
4. **首頁必載的 index.json 再瘦**：`aliases_show`、`images`、`counterparts_none`、`lens` 移到長內文，613KB → 558KB。
5. 小檔抓不到時，畫面會等整包到了再開；整包也失敗時顯示「下載失敗」而不是一直「載入中」。

## 三、前後數字

條件：3Mbps、處理器放慢四倍、沒有快取、gzip（比照 GitHub Pages）。

| 情境 | 之前 | 之後 |
|---|---|---|
| 首頁出現後馬上點第一個單元 | 8.6 秒 | 1.3–2.4 秒 |
| 學習模式點一張卡 | 6.6 秒 | 1.1–1.3 秒 |
| 研究模式點清單第一張卡 | 7.4 秒 | 0.9–1.1 秒 |
| 直接開單元連結 | 11.9 秒 | 4.0–4.3 秒 |
| 直接開專題連結 | 5.0 秒 | 3.2 秒 |
| 專題裡點一張卡 | 0.9 秒 | 1.1–1.3 秒 |
| 學習首頁出現 | 3.6 秒 | 3.5 秒 |
| 首頁下載量 | 1,823KB | 1,251KB |

「專題裡點一張卡」慢了約 0.3 秒：以前專題連結一開始就抓整包（所以專題頁本身要 5 秒），現在專題頁 3.2 秒就出來，點卡時才抓那張卡的小檔。

測試：e2e、research、dive、peoples、story-read、story、topics、images、era、perf、aliases 全部通過；另外測了「整包完全擋掉」13 個畫面都能用、「小檔擋掉」等整包到了仍能開。

## 四、留著的事

- 首頁出現前最大的一塊仍是 index.json（558KB）；其中地點資料 90KB、別名 49KB，再拆要動搜尋與地圖，這次沒動。
- 專題頁、主題頁的卡片連結還沒有加「滑過先抓」。
- `dist` 多了約 9MB 的小檔（單元檔重複收了卡片內文），對使用者沒有影響。
- 量測腳本作法：`click.cjs`（點擊到看見內容）、`full.cjs`（檔案完成順序）、`load.cjs`（首次出現），都是 Playwright＋CDP 限速；腳本沒有進 repo。

## 五、第二輪：首頁先出現（同日下午）

ZL 回饋：一開始載入不該這麼久，應該先載入第一眼看到的畫面、首頁功能與常用功能，細節慢慢載。

原因：畫面要等「整包程式 229KB」和「全部 406 張卡的資料 558KB」都到了才出現，這段時間只有「載入中」。

```
之前：全部程式＋全部卡片資料到齊 ─────── 約 3.9 秒 ───────▶ 首頁
現在：0.25 秒 骨架（寫在 index.html，不等下載）
      1.2 秒  首頁可以點（進入點程式 85KB＋home.json 18KB，共 116KB）
      背景    index.json → 單元與卡片的程式 → 地圖 → 時間軸 → 研究模式 → 故事、專題…
```

1. **home.json**（18KB）：建置時另寫一份只含首頁與清單頁要的資料。App 先用它畫首頁，`index.json` 到了再無縫換成完整資料（`src/lib/detail.ts` 的 `initStub`／`adoptCore`）。
2. **資料還沒到就點了**：點擊會被記住，先顯示骨架，資料一到自動打開。
3. **程式拆塊**（`src/chunks.tsx`）：研究模式、地圖、時間軸、單元、卡片、故事、專題各自一塊；畫面出來後依常用程度在背景預載，滑到單元上就先載；某一塊抓失敗會自動重試，再失敗顯示「重試」而不是白畫面。
4. **靜態骨架**：index.html 內嵌，第一個畫面不等任何下載。

| 3Mbps、處理器慢四倍、無快取 | 之前 | 之後 |
|---|---|---|
| 第一個畫面（不是空白） | 1.7 秒 | 0.25 秒 |
| 學習首頁可以點 | 3.9 秒 | 1.2 秒 |
| 首頁可點之前的下載量 | 817KB | 116KB |
| 首頁一出現就點單元，到看見第一步 | 6.1 秒 | 3.0 秒 |
| 研究模式外框出現 | 3.8 秒 | 1.1 秒 |
| 研究模式清單與時間軸 | 3.9 秒 | 4.0 秒 |
| 直接開單元連結 | 4.2 秒 | 3.0 秒 |
| 直接開故事閱讀頁 | 3.6 秒 | 2.7 秒 |

1Mbps 時首頁可點 8.1 秒 → 1.9 秒。

測試：12 組回歸測試＋「資料延後 6 秒」「程式塊抓失敗」「整包擋掉」全部通過；首頁在資料到達前後版面不跳（CLS 0.003）。

還留著的：
- 單元與卡片仍要等 index.json（558KB）才能打開，所以「首頁一出現就點單元」還要約 3 秒。下一步可以讓單元小檔自帶它用到的卡片基本資料，就不必等。
- 研究模式的清單與時間軸本來就需要全部卡片，時間沒變。
- 故事線清單頁的年代範圍（例如「1624–1934 年」）要等卡片資料到了才出現。
- `storyLite.ts`、`home-extra.css` 有幾段是從故事元件複製的，改故事元件時要一起看。

## 六、第三輪：簡化（同日傍晚）

ZL 回饋：整體都變慢了，開啟也是；請依 SRE 原則與第一性原理把做法簡單化。

**先承認量測的問題**：測試環境在快網路下，四個版本（11-11 之前、11-12 早上、兩輪效能修改後）都是 0.3–1.2 秒打開，重現不出變慢。也就是前幾輪都在用看不到真實情況的量測做決定。測試環境看不到的有三件事：

1. 網站剛更新後約十分鐘內，瀏覽器裡新舊檔案混在一起（GitHub Pages 快取 10 分鐘）。舊的 index.json 配新的小檔會觸發「版本不符 → 重抓兩次 → 改等 1.8MB 整包」；舊程式找不到已刪掉的程式塊會 404。ZL 每次都在剛更新完時測試，正好落在這段時間。（推論，沒有實測證據。）
2. 背景工作和使用者搶資源：1.8MB 下載＋約 5MB JSON 解析＋整個畫面重畫、517KB 古道資料、30 個預先載入的程式塊。
3. 外部向量底圖（測試一律擋掉外部網站）。

**第一性原理**：顯示一個畫面只需要「網頁 → 這個畫面的程式 → 這個畫面的資料」。使用者沒要求的東西不下載、不運算。

| 刪掉或改掉 | 之後 |
|---|---|
| 背景自動下載 index-detail.json（1.8MB） | 不再下載。長內文只來自每卡／每單元小檔；「結構對照」打開時才抓 data/match.json |
| 小檔的版本比對與重抓 | 拿到什麼用什麼；失敗重試一次，再失敗顯示「重試」 |
| 預先載入所有畫面的程式（warmUp） | 只載畫面上有的；滑到單元上才先載 |
| 程式塊抓失敗的多段補救 | 自動重新整理一次（30 秒內不重複），再不行顯示說明 |
| 每次都抓古道資料 | 放大到 5 級以上、古代年份、畫面在歐洲地中海一帶才抓 |
| index.html 的 PerformanceObserver 技巧 | 刪掉，程式一啟動就抓 index.json |

| 快網路、不操作 20 秒 | 之前 | 之後 |
|---|---|---|
| 學習首頁請求數／下載量 | 43 個／3,647KB | 19 個／1,202KB |
| 研究首頁請求數／下載量 | 43 個／3,653KB | 31 個／1,256KB |
| 15 秒內畫面卡住合計（處理器慢四倍） | 2,080ms | 約 800ms |
| 首頁／地圖出現 | 0.32／0.51 秒 | 0.35／0.52 秒（沒變） |

新舊檔案混用測試：舊的網頁與 index.json 配新的 data/，開單元與開卡片各只發 1 個請求、沒有錯誤。

**?perf=1**：網址加上這個參數，左下角會顯示這台裝置上的實際數字（第一個畫面、首頁可用、資料到齊、地圖出現各花多久；慢或大的檔案；外部網站；卡頓次數與最長一次；每秒畫面數；裝置資訊），可以按「複製」。之後效能判斷以這個為準。

程式行數（不含 perf 面板）：+199／−251。12 組回歸測試通過。
