# 載入變慢的原因與修正（2026-11-12）

做法：Fable 5.2（medium）量測、找原因、寫計畫與驗收條件；Sonnet 5.5（medium）實作；Fable 看差異、重新量一次再上線。

## 一、為什麼感覺變慢

首頁其實變快了，慢的是「首頁出現之後、點東西」的那幾秒。

```
0s        3.6s                            10.7s
│ 首頁出現 │ 點單元、點卡片都顯示「載入中」   │ 恢復正常
          └─ 在等 1.7MB 的背景大檔 index-detail.json ─┘
             它排在地圖元件（287KB）和古道資料（517KB）後面
```

11-11 的效能調整把單元每一步的內文也搬進這個大檔，首頁快了 1.5 秒，但點單元從「馬上有」變成「等大檔」。網路越慢，這段空窗越長。另外大檔的版本用的是建置時間，所以每次網站更新（最近一天好幾次）都要重新下載 1.7MB。

## 二、怎麼修

```
之前：點任何單元／卡片 ──等──▶ 整包 1.7MB
現在：點單元 ──▶ data/units/<id>.json（平均 31KB，含它用到的卡）
      點卡片 ──▶ data/cards/<id>.json（幾 KB）
      滑鼠移上去／手指碰到就先抓，點下去通常已經到了
      整包改成背景暖機，到了之後一切照舊
```

1. **點什麼抓什麼**：建置時多寫每個單元一個小檔；新模組 `src/lib/detail.ts`（`ensureCards`、`ensureUnits`、`intent` 預取）。各畫面只等自己要的那幾項，只有「結構對照」（要掃所有卡片內文）仍等整包。
2. **下載順序**：畫面要的小檔 → 底圖 → 整包 → 古道（最後）。
3. **不重抓沒變的資料**：整包版本改成內容雜湊（`index.json` 的 `detailV`），內容沒變時更新網站不會重新下載。
4. **首頁必載的 index.json 再瘦**：`aliases_show`、`images`、`counterparts_none`、`lens` 移到長內文，613KB → 558KB。
5. 小檔抓不到時，畫面會等整包到了再開；整包也失敗時顯示「下載失敗」而不是一直「載入中」。

## 三、前後數字

條件：3Mbps、處理器放慢四倍、沒有快取、gzip（比照 GitHub Pages）。

| 情境 | 之前 | 之後 |
|---|---|---|
| 首頁出現後馬上點第一個單元 | 8.6 秒 | 1.3–2.4 秒 |
| 學習模式點一張卡 | 6.6 秒 | 1.1–1.3 秒 |
| 研究模式點清單第一張卡 | 7.4 秒 | 0.9–1.1 秒 |
| 直接開單元連結 | 11.9 秒 | 4.0–4.3 秒 |
| 直接開專題連結 | 5.0 秒 | 3.2 秒 |
| 專題裡點一張卡 | 0.9 秒 | 1.1–1.3 秒 |
| 學習首頁出現 | 3.6 秒 | 3.5 秒 |
| 首頁下載量 | 1,823KB | 1,251KB |

「專題裡點一張卡」慢了約 0.3 秒：以前專題連結一開始就抓整包（所以專題頁本身要 5 秒），現在專題頁 3.2 秒就出來，點卡時才抓那張卡的小檔。

測試：e2e、research、dive、peoples、story-read、story、topics、images、era、perf、aliases 全部通過；另外測了「整包完全擋掉」13 個畫面都能用、「小檔擋掉」等整包到了仍能開。

## 四、留著的事

- 首頁出現前最大的一塊仍是 index.json（558KB）；其中地點資料 90KB、別名 49KB，再拆要動搜尋與地圖，這次沒動。
- 專題頁、主題頁的卡片連結還沒有加「滑過先抓」。
- `dist` 多了約 9MB 的小檔（單元檔重複收了卡片內文），對使用者沒有影響。
- 量測腳本作法：`click.cjs`（點擊到看見內容）、`full.cjs`（檔案完成順序）、`load.cjs`（首次出現），都是 Playwright＋CDP 限速；腳本沒有進 repo。
