# 卡片欄位定義（A／B／C／D）

> 本檔是卡片格式的「規格書」。`scripts/lib/fields.ts` 依本檔實作檢查規則；兩者若不一致，以本檔為準並修正程式。
> 原版欄位表未提供，本檔由 Claude 依 `history-river-prompt.md` 第 3 節重新起草（2026-10-24）。

## 0. 怎麼讀這份文件

```
一張卡 = 一個 .md 檔
┌────────────────────────────────────┐
│ ---                                │
│ YAML frontmatter                   │ ← 0 號欄位（A0/B0/C0/D0）：核心資料
│   id, type, name, time, place...   │    機器讀得懂，給搜尋/時間軸/地圖用
│   sources: [s1, s2...]             │ ← 來源清單，每筆有代號
│ ---                                │
│ ## A1 交戰方與聯盟結構               │ ← 1 號以後：內文段落
│ 雅典與提洛同盟……［s1］［s2］         │    每段至少引用一個來源代號
│ ## A2 ……                           │
└────────────────────────────────────┘
```

- **引用寫法**：在句子後面加 `[s1]`、`[s1][s3]`，代號對應 frontmatter `sources` 的 `id`。
- **查不到**：直接寫「未知」「估計」「示意」「來源不足」其中之一，並說明原因。這樣的段落可以沒有來源代號。
- **等級**（見 prompt 3.1）：
  - **核心**：每張卡必填，缺少 → `npm run validate` 報錯
  - **深入**：`track: west` 的希臘羅馬卡必填，缺少 → 警告；其他卡選填
  - **選填**：有可靠來源才填，不填不警告
- **完整度 %** ＝ 已填的（核心＋深入＋選填）欄位數 ÷ 該類型欄位總數。

## 1. 共用核心欄位（A0／B0／C0／D0，四種卡相同）

| 欄位 | 等級 | 說明 |
|---|---|---|
| `id` | 核心 | `類型-英文短名`，例 `war-peloponnesian`；全庫唯一，**不可改** |
| `type` | 核心 | `war`｜`commodity`｜`event`｜`building`｜`tech`｜`finance`｜`social`（第 6 期）｜`person`（深入專題，見 5e） |
| `name` | 核心 | 中文正式名稱（繁體） |
| `aliases` | 核心 | 其他譯名、英文名、常見錯字；給模糊搜尋用，至少 1 個。**請依知名度排序：最有名、最常用的寫在最前面**（卡片上就照這個順序顯示，先填滿兩行，其他收在「更多」）。簡體寫法會自動排到最後、和卡名一樣的會自動略過，不必自己處理 |
| `aliases_main` | 選填（舊欄位） | 想硬排到最前面的幾個別名（必須是 `aliases` 裡的字）。現在直接調整 `aliases` 的順序就好，通常不必寫 |
| `civilization` | 核心 | 文明，可多個，例 `[古希臘, 波斯]` |
| `track` | 核心 | `china`｜`west`｜`east`｜`other`；決定研究模式時間軸的軌道。`east`（第 6 期）＝臺灣、日本、朝鮮半島、東南亞，研究模式畫在「中國與東亞」軌 |
| `time.start` / `time.end` | 核心 | 年份整數，西元前用負數（前 431 年 → `-431`）；單一年份兩者相同 |
| `time.precision` | 核心 | `exact`｜`approx`｜`disputed` |
| `time.src` | 核心 | 年份的來源代號，例 `[s1, s2]` |
| `summary_line` | 核心 | 時間軸標籤，固定格式 `類型｜場域｜地點｜名稱` |
| `place.primary_field` | 核心 | 主場域，**只能 1 個**（選項見第 6 節） |
| `place.secondary_fields` | 選填 | 次場域，可多個 |
| `place.locations[]` | 核心 | 至少 1 個地點，每個地點欄位如下 |
| └ `name_ancient` | 核心 | 古地名（中文） |
| └ `name_modern` | 核心 | 今地名（中文＋國家），例 `伊斯坦堡（土耳其）` |
| └ `lat` / `lng` | 核心 | 座標；有 Pleiades 時取其代表點 |
| └ `pleiades_id` | 選填 | Pleiades 地名 ID（字串） |
| └ `precision` | 核心 | `exact`｜`schematic`｜`disputed`｜`unknown` |
| └ `role` | 選填 | 此地點在事件中的角色，例「主戰場」「出發港」 |
| `place.scale` | 核心 | `point`｜`line`｜`area` |
| `routes` | 選填 | 相關路線 id（見 `data/routes/routes.yaml`），地圖以線條呈現 |
| `structure_tags` | 核心 | 結構標籤，只能用 `docs/structure-tags.md` 詞表內的詞，至少 1 個 |
| `topics` | 核心 | 主題標籤（跟什麼東西有關，例如 交易所、紙幣、運河），只能用 `data/topics.yaml` 詞表內的名稱，至少 1 個；卡片內文要真的談到這個主題。說明見 `docs/topics.md` |
| `links` | 選填 | 相關卡片 id；反向連結由 build-index 自動計算 |
| `frameworks` | 選填 | 熱門分析框架 id（見 `data/frameworks.yaml`），對照頁會自動帶出批評 |
| `sources[]` | 核心 | 每筆：`id`、`title`、`url`、`accessed`（查閱日期）；第 6 期新增 `tier`（見第 8 節） |
| `verification` | 核心 | `AI草稿`（單一來源）｜`交叉確認`（主要事實 ≥2 個獨立來源）｜`爭議`（來源衝突，內文並列各方） |
| `lens_status` | 核心 | 雙軌解讀的狀態，固定為 `依公開資料推論，未對照原書` 或 `無直接論述` |
| `summary_card` | 選填 | `true` 表示摘要卡，只要求核心欄位 |
| `counterparts` | 深入 | 中西對照（第 2 期）。清單，每筆：`id`（另一條軌道的卡）、`note`（一句話說「哪裡相似、哪裡不同」）、`src`（來源代號）。找不到合適對照就寫字串 `無適當對照：原因`，不硬湊 |

## 5c. 文明欄位與分類樹（第 5 期新增）

`civilization` 照原文寫，篩選面板依 `data/civilizations.yaml` 把每個寫法對應到「地區 > 文明／國家 > 朝代時期」三層樹。中國朝代建議寫 `中國（唐）` 這種格式，會自動對應；特殊寫法（例如 `中國（秦、漢）`）在該檔的 `map` 指定路徑。對不上的寫法 `npm run validate` 會警告。

## 5e. P 人物卡（P0–P9，深入專題新增，2026-11-03）

一個人的一生與他的選擇。`type: person`、id 前綴 `person-`、檔案放 `cards/person/`、`summary_line` 第 1 段為「人物」。
寫人物卡的底線：**不寫成英雄傳**。P5「從另一邊看他」必填，要寫被他打敗、被他統治、被他犧牲的人怎麼看；P6 要寫評價怎麼隨時代改變。

```
time.start ＝ 生年、time.end ＝ 卒年（不確定就 precision: disputed）
place.locations ＝ 他一生去過的關鍵地點，每個都要有 year ──► 地圖依年份連成「人生軌跡」
person: { role, faction, name_romaji }
relations: 他和其他人物卡的關係（主從／同盟／聯姻／敵對／背叛／師友／親屬）──► 人物關係網
```

| 欄位 | 等級 | 說明 |
|---|---|---|
| `person.role` | 核心 | 一句話說他是誰，例「戰國大名、天下人」 |
| `person.faction` | 選填 | 所屬勢力，例「織田家」 |
| `person.name_romaji` | 核心 | 羅馬字拼音（日本人名用修正式赫本拼音），例 `Oda Nobunaga`；方便查外文資料 |
| `person.born` / `person.died` | 選填 | 若填要等於 `time.start`／`time.end` |
| `place.locations[].year` | 核心 | 他哪一年在這個地點（出生地、居城、關鍵戰場、死亡地），依年份排序 |
| `relations[]` | 深入 | 每筆：`id`（另一張人物卡）、`kind`（七選一）、`from`／`to`（起訖年，選填）、`note`（一句話）、`src`（來源代號）。只寫對方也有卡的人；關係寫一邊即可，程式會合併 |

| 代號 | 段落標題 | 等級 | 寫什麼 |
|---|---|---|---|
| P0 | （frontmatter） | 核心 | 第 1 節的共用核心欄位＋上表 |
| P1 | 出身與時代 | 深入 | 生在什麼家庭、什麼地方、當時的局勢給他什麼起點 |
| P2 | 一生的轉折 | 深入 | 依時間列 4–6 個轉折點（年份＋事件＋為什麼是轉折） |
| P3 | 關鍵決定：當時有哪些選擇 | 深入 | 挑 2–3 個決定，寫出他**當時**看得到的選項與代價，不用結果倒推 |
| P4 | 他改變了什麼 | 深入 | 制度、戰爭方式、經濟、信仰上留下什麼 |
| P5 | 從另一邊看他 | 深入 | 對手、被征服者、被統治者、女性、外國觀察者怎麼看他 |
| P6 | 評價怎麼變 | 深入 | 同時代、後世（江戶、明治、戰後）、現代史家的評價與理由 |
| P7 | 雙軌解讀 | 深入 | 同 A10 |
| P8 | 今日對照鉤子 | 深入 | 同 A11（只寫結構，不寫「今天的某某人像他」） |
| P9 | 不可類比的差異 | 深入 | 同 A12 |

學習模式「理解」層顯示 P1、P3、P4。

## 8. 學習模式欄位（第 6 期新增；研究模式可忽略）

```
有 learn 區塊 ─┬─ 欄位齊全（validate 0 錯誤）
               ├─ 每筆來源都有 tier，且至少 1 筆「一手」或「學術」
               ├─ verification 不是「AI草稿」
               └─ crosscheck.result ＝「通過」（沒參與寫作的查核者）
                         │
                         ▼
               這張卡才會出現在學習模式
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `importance` | 學習卡必填 | 1–3。學習模式三軌時間軸的「背景軌」只顯示 3（大事） |
| `learn.histories` | 必填 | 屬於哪些「XX史」，寫 `data/histories.yaml` 的史名或 id。程式另外會依 civilization 與卡片類型自動推算，兩者合併；`npm run validate -- --histories` 列出每張卡的結果 |
| `learn.perspectives` | 選填 | `{ history, text }`：從某個史看這件事，一句話 |
| `learn.why_care` | 必填 | 一句話告訴學生為什麼值得知道 |
| `learn.story` | 必填 | 150–250 字故事版，要附來源代號 |
| `learn.key_terms` | 必填 | `{ term, plain, example }`：名詞、白話解釋、生活例子 |
| `learn.primary_source` | 必填 | `{ text, from, src }`：一手史料短句（160 字內）、書名篇章、來源代號 |
| `learn.historiography` | 必填 | 史家怎麼吵：並列 2 種以上詮釋，各附來源 |
| `learn.money_scale` | 選填 | 金額換算成「一般勞工要工作幾天」，附來源 |
| `learn.misconceptions` | 選填 | 常見誤解 |
| `learn.pop_culture` | 選填 | 戲劇 vs 史實：清單，每條 `{ claim: 常見說法, fact: 史料怎麼說 [sN], src: [sN] }`。大河劇、遊戲、動漫常見但史料不支持的說法放這裡（深入專題的卡建議必填） |
| `learn.hindsight` | 金融卡必填 | 事後看很清楚的陷阱：後見之明、倖存者偏差；不構成投資建議 |
| `learn.exaggerated` | 選填 | 著名但可能被誇大的故事，說明誰質疑、根據什麼 |
| `crosscheck` | 學習卡必填 | `{ date, by, result: 通過｜不通過, notes }`：獨立查核者逐項核對年份、人名、數字與至少 2 個獨立來源的結果 |

**來源分級 `tier`**

| tier | 意思 | 例子 |
|---|---|---|
| 一手 | 當時的人留下的文字、檔案、統計 | 《史記》、修昔底德、荷蘭東印度公司檔案、政府公報 |
| 學術 | 學者寫的研究（論文、學術專書、大學或研究機構出版） | 期刊論文、中研院集刊、大學出版社專書 |
| 通論 | 可靠機構寫給一般人看的介紹 | 博物館、政府、央行、World History Encyclopedia |
| 百科 | 百科全書 | 維基百科、大英百科 |
| 摘要 | 書摘、演講整理、部落格 | 虎嗅、LitCharts、讀書筆記 |

舊卡沒標 tier 的來源，網頁上依網域推測並註明「推測」。學習卡一律要明標。

**學習模式只有一個詳細版**（2026-11-07 起，不再分國中「故事／理解」與高中「深入」三層）

卡片一次顯示：`why_care` ＋ `story` ＋ 一手史料 ＋ 全部段落 ＋ 史家怎麼吵 ＋ 思想家怎麼看（只在李彔或哈拉瑞有直接論述時出現，預設收起）＋ 名詞白話。`learn.understand` 欄位保留但目前不再用來篩段落。

## 圖片（images，選填）

網站第一次放卡片圖片（2026-11-03，深入專題）。只收 **Wikimedia Commons 上標示公有領域或 CC 授權**的真實作品（屏風、肖像畫、古地圖、文書照片），不自己裁切修圖。

```yaml
images:
  - url: https://upload.wikimedia.org/wikipedia/commons/x/xx/Odanobunaga.jpg   # 直接圖檔（Commons 檔案頁「原始檔案」連結，或 thumb 的 800px 版本）
    page: https://commons.wikimedia.org/wiki/File:Odanobunaga.jpg               # Commons 檔案頁
    title: 織田信長像
    creator: 狩野元秀（傳）          # 不詳寫「佚名」
    year: 1583                      # 作品年代，不詳寫「16 世紀」
    holder: 長興寺（愛知縣豐田市）    # 選填：收藏處
    license: Public domain          # 照 Commons 檔案頁的授權寫
    caption: 信長死後隔年所繪，是最常被引用的信長像。
```

validate 會檢查：url 是 upload.wikimedia.org、page 是 Commons File: 頁、title／creator／year／license／caption 都有、license 是公有領域或 CC。畫面：卡片頁頂端顯示第一張，點開看全部並附作者、年代、收藏處與 Commons 連結。

授權要**實際打開 Commons 檔案頁確認**才能填。寫卡時若環境連不到 Commons，先照格式寫好，再用 `npx tsx scripts/images-pending.ts strip` 把 images 區塊抽到 `data/pending-images.yaml`，查證後 `restore <card-id>` 放回。
